# Karten Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Der Gegenstand Karte zeigt im Vollbild das erkundete Gelände von oben (Fog of War), den eigenen Pfeil und alle Mitspieler als Punkte; das Erkunden wird immer aufgezeichnet und mit der Figur gespeichert.

**Architecture:** Neue Datei `js/karte.js` mit reinen Funktionen (Erkundungsraster, Kodierung, Farbe eines Feldes aus dem Generator, Umrechnung Welt ↔ Bild) und neue Datei `js/ui-karte.js` für das Vollbild (Canvas 2D). Die Erkundung liegt als Figurfeld `erkundet` (Schlüssel = Planeten-Seed) in `SC.Spielstand.FIGUR_FELDER`; das Spiel schreibt sie beim Betreten eines neuen 8 × 8-Felds fort. Die Karte in der Hand wird wie der Eimer über „Setzen“ benutzt.

**Tech Stack:** Klassische Skripte unter `SC`, Canvas 2D, `SC.Generator#hoehe(x, z)` / `#biom(x, z)`, Testseite `tests/index.html`.

**Spec:** `docs/superpowers/specs/2026-11-10-karten-design.md`

## Global Constraints

- Keine ES-Module, kein Bundler, kein npm; läuft per `file://`; ältere Safari (iOS) müssen laufen.
- Code-Kommentare, Commit-Nachrichten und Docs auf Deutsch; Commits mit `Refs #169`/`Fixes #169`; nicht pushen, GitHub-Issues/Board erst nach dem Push ändern.
- Block-IDs nie umnummerieren: neuer Gegenstand `KARTE: 114` (vor dem Eintragen `js/bloecke.js` auf freie IDs prüfen). Alte Spielstände bleiben gültig (fehlendes Feld → leere Karte).
- Raster **8 × 8 Blöcke je Feld**, 256 × 256 Felder je Planet (2048 / 8), ein Bit je Feld, Richtwert 8 KB je Planet (base64); **höchstens 6 Planeten je Figur** (der am längsten nicht besuchte fliegt raus); Schlüssel = `planet.seed`.
- Erkundungsradius: die Sichtweite, höchstens 64 Blöcke; aktualisiert wird nur beim Wechsel in ein neues Feld, nie jedes Bild.
- Rezept an der Werkbank: **2 Bretter + 1 Eisenerz → 1 Karte**; in der Kreativ-Auswahl.
- Farbe eines erkundeten Feldes aus dem Generator, nichts davon wird gespeichert; unerkundet = dunkel.
- Mitspieler als Punkte mit Namen, nur gleicher Planet, auch in unerkundeter Gegend; eigener Pfeil mit Blickrichtung; Bett (`bettPunkt`) als Symbol, falls vorhanden.
- Kein Erkunden und keine Karte im All.
- Netzprotokoll auf **14** (neue Block-ID 114).
- Version: **0.34.0** (`var V` in `index.html`; vorher auf dem Stand von `main` prüfen).
- Ladereihenfolge in `index.html` und `tests/index.html` identisch; `.claude/` nicht committen. Tests: `bash scripts/tests.sh` ohne Sandbox, erwartet `Fertig: N ok, 0 fehlgeschlagen`.
- Der Code ist dicht: mit `Read` + `offset`/`limit` arbeiten, kleine `Edit`s.

## Review Focus

- Spieler steht an der Weltkante (x oder z nahe 0 oder 2047): Erkundung und Anzeige laufen um den Ring herum, kein Feld außerhalb 0..255 (Task 2, 4).
- Gleichnamiger Planet einer anderen Welt (gleiche Id `start`, anderer Seed) zeigt nichts Erkundetes (Task 2).
- Spieler im All, Zuschauer, Planetenwechsel mitten im Lauf: keine Aufzeichnung auf dem falschen Planeten, kein Fehler (Task 5).
- Karte offen, während im Mehrspieler Positionen eintreffen oder ein Mitspieler geht: Punkte aktualisieren sich, kein Fehler (Task 4/5).
- Sehr alter oder beschädigter Spielstand: `erkundet` fehlt, ist `null` oder falsch lang codiert → leere Karte statt Absturz (Task 2).
